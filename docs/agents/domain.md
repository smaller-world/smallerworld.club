# Domain docs

This repo uses a single domain context.

Before exploring, read CONTEXT.md, the authoritative domain glossary, and ADRs
in docs/adr/ relevant to the task.

Use the glossary’s terms when naming domain concepts in code, tests, issues, and
proposals. Note real terminology gaps for domain-modeling.

Surface conflicts with existing ADRs explicitly, identifying the decision and
why it may need revisiting.

If a referenced document is absent, proceed silently. Create domain
documentation when terms or decisions are resolved.
